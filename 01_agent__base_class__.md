# Chapter 1: Agent (Base Class)

Welcome to the Qwen Agent tutorial! We're excited to help you build powerful AI agents. Let's start with the most fundamental concept: the `Agent`.

## What's an Agent? The Big Idea

Imagine you want to build a smart helper. This helper should be able to:

1.  Understand your requests (like "What's the weather in London?").
2.  Figure out how to answer (maybe it needs to check a weather website).
3.  Give you the answer.

In Qwen Agent, we call these smart helpers "Agents". The `Agent` base class is like the **master blueprint** for creating *any* kind of helper. It doesn't do the specific work itself, but it defines the basic structure and capabilities that all agents must have.

Think of it like the concept of a "Vehicle". A vehicle is something that transports things. That's the basic idea. But how does it move? Does it have wheels (like a car)? Wings (like a plane)? Tracks (like a tank)? The basic "Vehicle" concept doesn't specify *how*, just *that* it transports. Specific types like "Car" or "Plane" inherit the basic "Vehicle" idea and then add their own specific ways of working.

Similarly, the `Agent` base class defines that an agent receives information ([Messages](04_message__communication_structure__.md)) and produces a response. Specific types of agents, like `Assistant` (a helpful chatbot) or `ReActChat` (an agent that can reason and use tools), inherit from this base `Agent` class and define their *specific* step-by-step process (their unique `_run` method) for handling requests.

## Our First Agent: The `BasicAgent`

The simplest agent possible just takes your message and passes it directly to a Large Language Model (LLM) – the "brain" – to get a response. Qwen Agent provides this as `BasicAgent`. Let's see how to use it.

```python
# 1. Import the necessary classes
from qwen_agent import BasicAgent
from qwen_agent.llm import get_chat_model

# 2. Set up the LLM (the "brain")
#    (We'll cover LLMs in detail in the next chapter!)
llm_config = {'model': 'qwen-turbo'} # Use a Qwen model
llm = get_chat_model(llm_config)

# 3. Create our BasicAgent, giving it the LLM
simple_agent = BasicAgent(llm=llm)

# 4. Prepare our message
messages = [{'role': 'user', 'content': 'Hello!'}]

# 5. Run the agent and get the response stream
response_stream = simple_agent.run(messages=messages)

# 6. Print the response chunks as they arrive
for chunk in response_stream:
    print(chunk) # Each chunk is a list of Message objects/dicts
```

**Explanation:**

1.  **Import:** We bring in `BasicAgent` and a function to set up our LLM.
2.  **LLM Setup:** We configure the Large Language Model we want the agent to use. Don't worry too much about this line yet; we'll dive into [BaseChatModel (LLM Interface)](02_basechatmodel__llm_interface__.md) in the next chapter.
3.  **Create Agent:** We instantiate `BasicAgent`, telling it which LLM to use.
4.  **Message:** We create a list containing our message. Messages follow a specific structure ([Message (Communication Structure)](04_message__communication_structure__.md)), usually including a `role` (`user`, `assistant`, `system`) and `content`.
5.  **Run:** We call the `run` method, passing in our message list. This starts the agent's process. It returns a *stream* (an iterator), meaning the response might come back in pieces.
6.  **Print Output:** We loop through the stream and print each piece of the response as it's generated by the LLM.

**Expected Output (might vary slightly):**

```
[{'role': 'assistant', 'content': 'Hello'}]
[{'role': 'assistant', 'content': ' there! How can'}]
[{'role': 'assistant', 'content': ' I help you today?'}]
# ... potentially more chunks ...
[{'role': 'assistant', 'content': 'Hello there! How can I help you today?'}] # Final complete message
```

You'll see the assistant's reply ("Hello there! ...") being printed chunk by chunk. The `run` method handles getting this response from the LLM via the `BasicAgent`'s simple logic.

## Under the Hood: How `Agent.run()` Works

What happens when you call `agent.run(messages)`? Here's a simplified step-by-step:

1.  **Input Processing (`run`):** The main `run` method takes your `messages`. It might do some initial setup, like adding a default system message (initial instructions for the LLM) if one wasn't provided.
2.  **Core Logic (`_run`):** The `run` method then calls the internal `_run` method. This is the crucial part! **Each specific agent type (like `BasicAgent`, `Assistant`, etc.) defines its own unique `_run` method.** This method contains the agent's specific workflow. For `BasicAgent`, the `_run` method is very simple: it just prepares to call the LLM. More complex agents might decide here whether to call an LLM, use a [Tool](03_basetool__tool_interface__.md), or something else.
3.  **Execution (`_call_llm` / `_call_tool`):** The `_run` method often uses helper methods like `_call_llm` (to talk to the [LLM](02_basechatmodel__llm_interface__.md)) or `_call_tool` (to use a [Tool](03_basetool__tool_interface__.md)).
4.  **Output Streaming (`_run` -> `run` -> User):** The results (e.g., text from the LLM) are typically streamed back. The `_run` method yields these results piece by piece, the `run` method formats them, and then yields them back to your code.

**Key Takeaways:**

*   **`ABC` and `@abstractmethod`:** `Agent` is an Abstract Base Class. This means you can't create an `Agent` object directly. It's just a blueprint. The `@abstractmethod` on `_run` forces any child class (like `BasicAgent`) to provide its *own* version of the `_run` method. This ensures every agent defines its specific behavior.
*   **`__init__`:** The constructor sets up the essentials: the [LLM](02_basechatmodel__llm_interface__.md), available [Tools](03_basetool__tool_interface__.md) (if any), and the initial system instructions.
*   **`run`:** The public method you call. It handles common tasks (message prep, response formatting) and then delegates the core work to `_run`.
*   **`_run`:** The heart of a specific agent. This is where the unique logic resides.
*   **`_call_llm` / `_call_tool`:** Convenient internal helpers for subclasses to interact with LLMs and Tools.

Now, let's see how `BasicAgent` implements the required `_run` method:

```python
# File: agent.py (Inside the BasicAgent class)

class BasicAgent(Agent): # Inherits from Agent

    def _run(self, messages: List[Message], **kwargs) -> Iterator[List[Message]]:
        # BasicAgent's implementation is simple:
        # Just call the LLM with the messages.
        return self._call_llm(messages, **kwargs)
```

As you can see, `BasicAgent` fulfills the requirement by providing an `_run` method. Its logic is straightforward: it directly calls the `_call_llm` helper method inherited from the base `Agent` class.
